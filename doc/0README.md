# Stage 1 导读

这一阶段对应 `learn/stage-1-core-agent`。

如果你第一次接触这个项目，建议把这一阶段当成“最小可运行 Agent”来看，不要急着理解全部细节。这里的目标只有一个：先看清楚一个 Agent 是怎么接收输入、调用大模型、执行工具、再把结果返回给用户的。

## 这一阶段实现了什么

- 一个最小可运行的 ReAct Agent
- 两个最基础的工具：`read_file`、`exec_shell`
- 一个简单的命令行交互入口
- 一份基础的消息上下文管理

你可以先把它理解成：

- `Agent`：会“接收问题 -> 思考 -> 调工具 -> 继续回答”的程序
- `ReAct`：先想，再做，再根据结果继续想的一种循环
- `Tool`：给 Agent 用的外部能力，比如读文件、执行命令
- `Context`：对话历史，也就是 Agent 目前“记得什么”
- `Eino`：这个项目使用的 Go LLM/Agent 框架，这一阶段只需要把它当成底层支撑

## 推荐阅读顺序

先按下面顺序读，不要跳：

1. [doc/doc.md](./doc.md)
   先看项目整体结构，知道有哪些模块，各自负责什么。
2. [doc/agent.md](./agent.md)
   再看 Agent 主循环，理解一次完整请求是怎么跑起来的。
3. [doc/eino_usage.md](./eino_usage.md)
   如果你对 `Eino` 还陌生，再补这篇，知道项目具体用了它的哪些能力。
4. [doc/stage1_review.md](./stage1_review.md)
   最后看这篇，把它当作“第一阶段还不完美的地方”，帮助你理解后面为什么会继续演进。

## 读代码时建议关注什么

这一阶段不要追所有文件，先抓三条主线：

- 入口：`cmd/miniagent/main.go`
- 主循环：`internal/agent/agent.go`
- 工具注册：`internal/tools/registry.go`

只要你能回答下面三个问题，这一阶段就算读懂了：

- 用户输入是从哪里进入系统的？
- LLM 什么时候决定调用工具？
- 工具结果是怎么回到后续对话里的？

## 这一阶段暂时没解决什么

为了保持第一阶段足够简单，这里还没有重点解决下面这些问题：

- 流式输出
- 更多工具类型
- 工具执行策略优化
- 上下文压缩
- Skill 和长期任务

所以读到“这里还很原始”是正常的，这正是后面几个 learning 分支要继续展开的内容。

## 进入下一阶段前，你应该已经理解

- 一个最小 Agent 至少由哪些部分组成
- 为什么 Agent 不只是一次 LLM 调用，而是“LLM + 工具 + 上下文”的循环
- 为什么第一阶段已经能工作，但还不够适合真实开发任务

理解这些之后，再切到 `learn/stage-2-tools-task`，去看流式输出、更多工具和上下文管理是怎么一步一步加上去的。
