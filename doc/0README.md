# Stage 5 导读

这一阶段对应 `learn/stage-5-current`，也是当时对外公开的 baseline。

前面几个阶段更像是在一路搭能力、补结构；到了这一阶段，重点不再只是“继续引入新概念”，而是把已经逐步形成的能力收拢成一个相对完整、可对外展示、可继续演进的版本。所以读这一阶段时，最好把它看成“前四个阶段的阶段性收束”，而不是一个全新主题。

## 这一阶段最适合怎么读

不要把 Stage 5 当成“从零开始的第一站”，更适合把它当成回顾总结站。也就是说：

- 如果你是第一次了解项目，建议还是从 Stage 1 开始往后看
- 如果你已经走过前面几个分支，这里适合拿来确认当时公开 baseline 的整体状态
- 如果你想知道“到这个节点为止，这个项目已经像什么样子了”，这一阶段最有参考价值

## 到这一阶段为止，项目已经具备什么

- ReAct 主循环已经稳定存在
- 工具系统已经从最小能力扩展到更接近 Coding Agent 的基础工具组
- 上下文管理与压缩已经进入主线
- Skill、Prompt、Task、命令系统都已经形成基本结构
- TUI、Session、MCP 相关能力已经进入公开基线

换句话说，这一阶段不是只展示一个点状功能，而是在展示“这条 learning 路线目前收敛出来的整体形态”。

## 推荐阅读顺序

建议按“从整体到模块”的顺序读：

1. [README.md](../README.md)
   先看这一阶段对外是怎么介绍自己的，理解它想把自己呈现成什么。
2. [doc/agent.md](./agent.md)
   重新抓住主循环，因为它依然是整个系统的中心。
3. [doc/tools.md](./tools.md)
   看工具系统已经成长到什么程度，以及边界是否更清楚了。
4. [doc/context.md](./context.md) 和 [doc/task.md](./task.md)
   理解上下文与任务这两条长期运行所必需的主线。
5. [doc/cli.md](./cli.md)、[doc/skill.md](./skill.md)、[doc/mcp.md](./mcp.md)
   最后再补交互层、技能层和外部扩展层。

## 这一阶段建议重点看什么

读 Stage 5 时，最值得关注的不是“又多了哪一个功能”，而是下面这些问题：

1. 前面几个阶段引入的能力，到这里有没有形成相对稳定的边界？
2. 这个公开 baseline 更像一个“可用系统”还是“持续实验中的原型”？
3. 哪些地方已经比较完整，哪些地方还明显只是阶段性方案？

只有带着这些问题去看，Stage 5 才会真正有价值。

## 读者可以先这样理解几个关键词

- `baseline`：当前对外公开、相对稳定、可作为参考起点的版本
- `公开基线`：不是说以后不会变，而是说这个点适合被外部读者拿来理解项目
- `收敛`：前面不断增加的能力，开始被整理成一个相对统一的系统形态
- `阶段性方案`：当前可用，但未来仍可能继续调整的设计

## 读代码时建议关注什么

如果你已经看过前面几个阶段，这里推荐把注意力放在“整体拼图”上：

- `cmd/5hagent/main.go`
- `internal/agent/`
- `internal/tools/registry.go`
- `internal/context/`
- `internal/cli/`
- `internal/task/`
- `internal/mcp/`

你可以边读边回答下面这些问题：

- 主入口现在是怎样把各模块拼起来的？
- 哪些能力已经进入默认主线，哪些还更像扩展？
- 前几个阶段提到的概念，到这里是否已经落成稳定文件和模块？

## 这一阶段和 develop 的区别应该怎么理解

`learn/stage-5-current` 更适合被理解成“当时的公开学习快照”，而不是持续滚动开发分支。也就是说，它的意义是让读者看到一条学习路线走到这里时，项目处在怎样的状态；后续新的开发会继续发生，但不应该反过来破坏这个阶段快照本身的可读性。

## 读完这一阶段后，你应该能得到什么

- 能用一段比较完整的话描述 5hAgent 到这一阶段为止已经是什么
- 能看懂这个项目是怎样从最小 Agent 一步步演进到公开 baseline 的
- 能区分哪些内容属于稳定主线，哪些只是未来还会继续变化的部分

如果你已经顺着 Stage 1 到 Stage 5 读完，那么这条 Learning 路线的第一轮理解就已经完成了。之后再去看 `develop`，就不会是“第一次见整个项目”，而是在已有地图的基础上看它继续往前长。
