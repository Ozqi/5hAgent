# read我希望做的更复杂

## 对于md文件
应该有更多高效的能力。

递归只读取所有标题
读取指定分级标题下的内容。

剪切某标题
复制、删除某标题下的内容
删除某标题下的内容


## think
这些可以不可以又Agent自己创建，持久的放到一个自动复用的工具区， 和 tool use一样平行。

## 确定结论

- Markdown 结构化读取是确定值得做的工具增强；优先放在现有 base 工具体系下，不需要先引入动态工具平台。
- 推荐最小能力：
  - 列出 Markdown 标题树；
  - 读取某个标题范围；
  - 替换/删除某个标题范围。
- “剪切/复制”本质是读取范围 + 写入范围，可以后置；先实现读标题和读 section，风险最低。
- Agent 自己持久创建工具这件事应归到“动态工具注册”设计，必须有脚本目录、权限边界、`--help`/schema 生成和人工审查；不能让 LLM 任意生成后立即成为默认工具。
- 本条后续最小实现点建议：新增 `base.read_md` 或扩展 `base.read_file` 的 Markdown mode，先只读不写。
