# 提升读者掌控力
读者指的是我本人， 我之前是每次vibe coding以后更新文档，然后我看文档。

现在我一直用Ai并行开发新功能，产出太多没法了解；现在文档已经太多太多了，而且代码更新很快，每次更新代码都全量读文档再edit，效率低，token消耗高。

## 确定结论

- 文档不能继续靠“每次改动全量更新全部文档”维持一致；应改成变更摘要 + 模块索引 + 按需更新。
- 每次提交应在 commit message 或对应 TODO 中写清楚：改了什么、为什么改、验收看哪里。
- `doc/0README.md` 只做导航，不承载所有细节；模块文档只在模块边界或关键行为变化时更新。
- 对读者最有用的是“当前状态入口”：分支状态、未完成 TODO、最近提交摘要、人工验收 checklist。
- 后续可考虑新增一个轻量 `doc/current.md` 或维护 `开发日志.md` 的阶段摘要，但不应要求每个 Agent 每次全量读完整 doc。
