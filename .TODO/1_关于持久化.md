# 关于持久化

## 已对齐结论

- **一份 Session 真源**：Session 保存完整对话历史，用户可以查看全部历史，也可以一键导出。
- **Context 是 Session 的投影**：每轮真正发给 LLM 的内容由 Session 加 Context 状态生成，通常只是 Session 的子集。
- **Agent 操作 Context 状态**：Agent 可以通过工具调整 pin、mask、summarize、audit 等投影状态；Session 原始历史由系统自动维护。
- **Context 状态随 Session 持久化**：pin、mask、summary、projection metadata 进入同一份 Session 存储，恢复会话后能重建同一份 LLM 输入。
- **Report / Worklog 是执行产物**：归项目 `.walle/` 管理，用于任务验收和过程追踪，不承担聊天历史真源职责。

## 存储分层

| 层 | 真源 | 用途 |
| --- | --- | --- |
| Session | `~/.walle/sessions/*.jsonl` | 完整聊天历史、用户查看、导出、恢复。 |
| Context | Session + projection metadata | 当前 LLM 可见上下文。 |
| Context 状态 | Session metadata / message extra | pin、mask、summary、projection 规则。 |
| Report / Worklog | 项目 `.walle/` | headless / daemon process 的执行产物。 |

## Agent 可操作边界

Agent 面向 Context 工作，不能默认改写 Session 原始历史。

第一版允许：

- `context.context {"action":"inspect"}`：查看完整历史索引、当前投影状态和可操作范围。
- `context.context {"action":"pin"}`：标记单条 message 一直进入投影，并防止被 mask。
- `context.context {"action":"unpin"}`：取消单条 message 的 pin。
- `context.context {"action":"mask"}`：让单条 message 退出 LLM 投影，Session 保留原文。
- `context.context {"action":"unmask"}`：取消单条 message 的 mask。
- `context.context {"action":"audit"}`：查看 Context 状态变更记录。

第一版禁止：

- Agent 直接删除 Session 原始消息。
- Agent 直接重写 Session 原文。
- Agent 伪造完整历史。

`edit` 保留为修正错误历史的显式改写能力；隐藏、忽略、减少注意力的需求走 `mask`。

## 工具命名

工具名使用固定语法：

```text
<domain>[.<resource>...].<action>
```

规则：

- 最后一段是 action。
- 前面的段是 domain path。
- `rootDomain` 用于工具分组展示。
- 完整名称全局唯一注册。
- 默认控制在 2 到 3 段；超过 3 段时优先把层级收进参数。

示例：

```text
context.context
terminal.run
terminal.session.create
```

## 动态工具

动态工具同样使用 `<domain>[.<resource>...].<action>`，统一放在 `terminal` 域：

- `terminal.<name>.<action>`：运行期注册工具。
- 注册元数据区分命令模板、临时脚本或其他 executor。
- `<name>` 是能力名，最后一段 `<action>` 是动作名。
- 第一版只做运行期注册，不落盘；后续有复用需求再放入 skill 或项目工具目录。

示例：

```text
terminal.repo_diff.check
terminal.doc_index.refresh
```
