## debug 打印 LLM 请求内容

原则：足够 lazy，先复用现有 `--debug` 和 logger，不新增 tracing 系统。

目标：

- [x] `--debug` 打开时，在每次调用 LLM 前打印/落盘本次发给 LLM 的完整逻辑请求。
- [x] 第一版只要求覆盖 Agent 层能直接拿到的内容：provider/model、messages 的 role/name/content/tool_calls/tool_call_id、tool result、当前 model options。
- [x] 不打印 API key、鉴权 header 或 `.env` 原文；如果某个字段无法从当前抽象层拿到，就先标注为 unavailable，不为此重写 LLM client。
- [x] 输出优先写到现有 debug log；不要默认刷屏 TUI。后续如果确实需要，再考虑单独的 `/debug request` 或 worklog 附件。
- [x] 内容要可复制复盘：保留消息顺序和 role，不做摘要；只允许对明显敏感字段做固定掩码。

验收：

- [x] 开启 `--debug` 后，日志中能看到一次 LLM 调用的完整 messages 和模型信息。
- [x] 普通非 debug 运行没有额外输出和落盘。
- [x] 日志里不出现 API key。
